# نئون لاین | نسخه آزمایشی آماده اتصال به Supabase

وب‌سایت فارسی RTL برای برند دیجیتال مارکتینگ نئون لاین. رابط کاربری با HTML/CSS/JavaScript ساده ساخته شده تا وابستگی به فرایند build نداشته باشد و انتقال به میزبان استاتیک یا هاست دامنه‌دار ساده بماند.

## در این نسخه چه آماده است؟
- صفحات خانه، خدمات، نمونه‌کارها، مرجع دانش، درباره ما، تماس، حریم خصوصی و 404.
- طراحی واکنش‌گرا، منوی موبایل، تم روشن/تیره و فونت Vazirmatn.
- صفحه ورود مدیر با Supabase Auth.
- پنل مدیریتی قابل اتصال برای مقالات، دسته‌ها، صفحات، خدمات، نمونه‌کارها، سرنخ‌های تماس و تنظیمات SEO.
- فایل `supabase/schema.sql` برای ساخت جدول‌ها، شاخص‌ها، سیاست‌های RLS و داده اولیه خدمات.
- فرم تماس آماده ذخیره در جدول `leads` پس از پیکربندی Supabase.

**محدودیت شفاف:** قابلیت‌های متصل به داده تا وقتی یک پروژه Supabase واقعی بسازید، SQL را اجرا کنید و `config.js` را تنظیم کنید فعال نمی‌شوند. این پروژه هنوز به هیچ حسابی متصل یا در GitHub منتشر نشده است. محتوای صفحات عمومی فعلاً محتوای اولیه است؛ پنل CMS آماده مدیریت است، اما اتصال کامل محتوای تمام صفحات عمومی به CMS و تولید خودکار sitemap از پنل، مرحله توسعه بعدی است.

## 1) ساخت پروژه Supabase
1. در Supabase یک پروژه بسازید و از `Project Settings → API` آدرس پروژه و کلید عمومی (`publishable` یا `anon`) را بردارید.
2. فایل `config.js` را باز کنید و فقط این دو مقدار را جایگزین کنید:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
3. **هرگز** کلید `service_role` یا کلید محرمانه را در فایل‌های فرانت‌اند، GitHub یا `config.js` قرار ندهید.
4. از `SQL Editor`، کل محتوای `supabase/schema.sql` را اجرا کنید.
5. از بخش `Authentication → Users` یک کاربر مدیر بسازید و UUID کاربر را کپی کنید.
6. در SQL Editor دستور زیر را با UUID واقعی و نام نمایشی اجرا کنید:

```sql
insert into public.profiles (id, display_name, role)
values ('UUID-USER-FROM-AUTH', 'مدیر نئون لاین', 'admin')
on conflict (id) do update set role = 'admin', display_name = excluded.display_name;
```

7. `admin-login.html` را باز کنید و با ایمیل/رمز همان کاربر وارد شوید.

### نقش‌ها و امنیت
- سیاست‌های RLS برای جداول محتوا فعال هستند؛ کاربران عمومی فقط محتوای منتشرشده را می‌خوانند.
- سرنخ‌های تماس برای کاربر عمومی فقط قابلیت `INSERT` دارند و خواندن/ویرایش آن‌ها به اعضای مجاز محدود است.
- فقط حسابی که در `profiles` نقش `admin` یا `editor` دارد باید پنل را مدیریت کند.
- کلید عمومی Supabase در فرانت‌اند طبیعی است؛ امنیت با RLS و سیاست‌های دسترسی اعمال می‌شود، نه مخفی کردن anon/publishable key.
- برای انتشار واقعی، روی فرم تماس rate limit / ضداسپم سمت سرور یا Edge Function اضافه کنید و سیاست نگهداری اطلاعات شخصی را نهایی کنید. RLS به‌تنهایی جایگزین rate limiting نیست.

## 2) آزمایش محلی
چون از `fetch` و کتابخانه‌های CDN استفاده می‌شود، پروژه را ترجیحاً از طریق یک static server باز کنید نه `file://`. ساده‌ترین روش با Python:

```bash
python -m http.server 8080
```

سپس به `http://localhost:8080` بروید. برای کار با Supabase، اینترنت و تنظیمات CORS/URL در Authentication لازم است. نشانی localhost و نشانی نهایی را در `Authentication → URL Configuration` تنظیم کنید.

## 3) GitHub و انتشار آزمایشی
1. یک repository جدید بسازید و محتویات این پوشه را در ریشه آن قرار دهید.
2. از `Settings → Pages` روش انتشار متناسب با repository را تنظیم کنید، یا برای سایت عمومی تجاری ترجیحاً GitHub را فقط برای نسخه‌بندی کد نگه دارید و فرانت‌اند را با Cloudflare Pages یا میزبان استاتیک سازگار منتشر کنید.
3. نشانی آزمایشی منتشرشده را در Supabase `Authentication → URL Configuration` به‌عنوان Site URL و Redirect URL مجاز اضافه کنید.
4. برای مخزن پروژه‌ای GitHub Pages، مسیرهای نسبی فایل‌ها را حفظ کنید؛ از مسیرهایی مثل `/styles.css` استفاده نکنید مگر `base path` تنظیم شده باشد.

## 4) انتقال به دامنه و هاست آینده
- سورس سایت و فایل SQL قابل انتقال‌اند؛ Supabase می‌تواند به‌عنوان بک‌اند باقی بماند.
- در هاست جدید، فایل‌های استاتیک را آپلود کنید و `config.js` را با تنظیمات همان پروژه Supabase نگه دارید.
- دامنه نهایی را به Supabase Auth در فهرست URLهای مجاز اضافه کنید.
- HTTPS را فعال کنید، ایمیل/شماره تماس نمونه را جایگزین کنید، سیاست پشتیبان‌گیری و ضداسپم را نهایی کنید و همه سیاست‌های RLS را دوباره تست کنید.

## نسخه v1 — ویرایشگر پیشرفته مقاله
- ویرایش دیداری محتوا با قالب‌بندی H1/H2/H3، پاراگراف، پررنگ، مورب، فهرست‌ها و لینک.
- حالت ویرایش مستقیم HTML و واردکردن فایل `.html` (حداکثر ۲ مگابایت).
- پاک‌سازی اولیه HTML هنگام ذخیره برای حذف اسکریپت‌ها، iframeها، handlerهای رویداد و URLهای `javascript:`. این پاک‌سازی سمت مرورگر جایگزین sanitization سمت سرور هنگام نمایش محتوای عمومی نیست؛ محتوای ذخیره‌شده را در فرانت‌اند با روش امن رندر کنید.
- تصویر شاخص از طریق URL یا بارگذاری فایل به Storage، همراه عنوان تصویر و متن جایگزین (alt).

### ارتقای دیتابیس برای v1
پس از اجرای schema اصلی، یک بار فایل `supabase/article-editor-migration.sql` را در Supabase → SQL Editor اجرا کنید. این migration ستون‌های `cover_title` و `cover_alt` و bucket عمومی `article-images` را آماده می‌کند و سیاست بارگذاری را به پروفایل‌های دارای نقش `admin` یا `editor` محدود می‌سازد. اگر migration با خطای permission روبه‌رو شد، آن را با نقش مالک پروژه در SQL Editor اجرا کنید.

### آزمایش مقاله
1. پنل مدیریت را با حساب مدیر باز کنید و به مقالات بروید.
2. «مورد جدید» را بزنید؛ در ویرایش دیداری یک H1 و چند H2 بسازید، یا به حالت «کد HTML» بروید.
3. برای واردکردن فایل HTML، فایل را انتخاب کنید؛ اسکریپت‌های فایل عمداً حذف می‌شوند.
4. یک تصویر شاخص بارگذاری کنید یا URL بدهید، سپس عنوان و متن جایگزین را تکمیل کنید.
5. ابتدا با وضعیت پیش‌نویس ذخیره کنید و در Supabase → Table Editor → `articles` مقدار `body`, `cover_url`, `cover_title`, `cover_alt` را بررسی کنید.


## نسخه v2: انتشار پویا مقالات
- `knowledge.html` و بخش مرجع دانش صفحه اصلی فقط مقالات منتشرشده را از Supabase دریافت می‌کنند.
- صفحه اشتراک‌گذاری مقاله: `article.html?slug=your-article-slug`.
- نمایش عمومی نیازمند `status = published` و `published_at` معتبر و گذشته است.
- ستون‌های `cover_title` و `cover_alt` باید با `supabase/article-editor-migration.sql` اضافه شده باشند.
- بررسی کنید RLS اجازه خواندن عمومی فقط مقالات منتشرشده را بدهد. نمونه سیاست پس از بررسی سیاست‌های موجود:

```sql
alter table public.articles enable row level security;
drop policy if exists "Public can read published articles" on public.articles;
create policy "Public can read published articles" on public.articles for select to anon, authenticated using (status = 'published' and published_at is not null and published_at <= now());
```

HTML مقاله پیش از نمایش در مرورگر پاک‌سازی می‌شود. برای GitHub Pages و میزبان‌های استاتیک از الگوی `article.html?slug=...` استفاده شده است.
